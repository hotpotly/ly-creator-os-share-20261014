# LY Creator OS使用指南

LY Creator OS是一套本地优先的自媒体创作工作台。Mac端负责灵感、选题、项目、文案、制作、发布、排期、收入和资料管理；Android端负责低打扰记录，并可在同一可信局域网内把内容加密同步到Mac。

这份说明以当前源码已经实现的入口为准。界面中显示“查看规划”的工具仍是后续能力，不应当作已经可用的功能。

## 1.使用前先知道

- Mac安装包当前只构建Apple Silicon版本，适用于M系列芯片Mac。
- 所有项目、灵感、台账和设置默认保存在本机，不会跟随Git源码上传。
- 新安装只创建内容方向、模板和基础风格，不再自动塞入演示项目、示例灵感、排期或任务。
- AI并不是后台自动运行。只有你验证连接或明确发起任务时，App才会调用对应CLI或API。
- Android端最低要求Android 12。手机先离线保存，Mac返回持久化成功回执后才标记为已同步。
- 当前仓库未附开源许可证。可以私下协作使用，但公开发布或允许再分发前，应先补充明确的许可证。

## 2.第一次打开后的推荐设置顺序

打开左下角`设置`，右上角的小菜单可以切换五类设置。

### 2.1通用

1. 选择浅色或深色外观。
2. 选择暖灰绿或飞书式视觉风格。
3. 查看`当前App版本`，确认自己使用的是`Applications安装版`还是`临时运行版`。

### 2.2工作区

1. 调整侧栏分组、显示项目和常用入口。
2. 设置新项目默认发布平台。
3. 设置默认内容方向，或保留`交给AI归类`。
4. 选择新建项目后自动归类，还是只在手动点击时归类。

### 2.3首页与待办

1. 按自己的工作方式修改待办分类名称、颜色和权重。
2. 选择天气城市；城市只保存在本机。
3. 首页左右分栏可拖动，双击分隔条可恢复默认比例。

### 2.4 AI与发布

1. 如果本机已经安装并登录Codex CLI或Claude CLI，先查看它们的可用状态。
2. 也可以添加OpenAI、Anthropic、Gemini、DeepSeek或OpenAI兼容API。
3. 填写模型ID后执行`验证连接`，再选择默认AI和备用AI。
4. 添加自己的发布平台账号和账号定位。联系方式只显示脱敏结果。
5. 按实际业务保留或调整商单平台。

API key使用macOS安全存储加密，Renderer不会读取或回显已经保存的完整密钥。调用云端AI前，仍要确认本次选择的文案、资料和文件可以发送给该服务商。

### 2.5数据与设备

1. 先点一次`立即备份`，确认本机备份可用。
2. 收入数据较敏感时，开启收入台账隐私锁。
3. 需要NAS时，选择Finder中已经挂载的SMB目录；第一次正式归档前先做大文件、断线和重试验证。
4. 需要手机采集时，开启`Android快速记录`局域网接收。

## 3.日常创作流程

### 3.1先记录，不急着整理

- 点击顶栏`快速记录`，或使用`Command＋Shift＋Space`打开小窗口。
- 可以输入文字并添加媒体；从项目内部打开时会自动关联当前项目。
- 新内容进入`灵感库`，原始内容会被保留，之后再决定内容方向、项目和用途。
- 商单的客户反馈从项目内大纲或文案区域记录，不进入全局快速记录。

### 3.2在灵感库处理收件箱

1. 打开`灵感库`查看待处理、待复核和已处理记录。
2. 按内容方向、关联项目和来源筛选。
3. 可以手动归类，也可以明确发起Codex归类。
4. 完全相同的记录可以执行查重整理。
5. 适合继续发展的内容可以进入选题，或直接关联已有项目。

### 3.3在选题管理中决定做不做

- 为选题填写标题、核心角度、内容方向、优先级、日期和下一步动作。
- 使用不同阶段区分新候选、待评估、已立项、已完成、已归档或已搁置。
- 确定制作后创建项目；完成或归档项目时，对应选题状态会一起更新。

### 3.4创建和推进内容项目

点击顶栏`新建项目`，填写标题、内容方向、模板、发布平台和商单属性。项目通常按以下模块推进：

1. `概览`：项目说明、方向、平台、进度和基本信息。
2. `资料`：导入文件、文件夹、链接、图片、PDF和项目笔记；把最重要的内容设为主要参考。
3. `大纲`：手写大纲，或在确认输入后分别调用Codex与Claude生成候选。
4. `文案`：使用对话、候选、版本对比和定稿流程整理完整文案。
5. `拍摄剪辑`：管理制作清单、制作记录和部分AI视频入口。
6. `后期`：处理字幕和封面候选。
7. `发布`：根据定稿准备平台标题、简介、封面、字幕和人工发布交接。
8. `金额`：只在商单项目中出现，用于记录金额、返点、成本、发票和回款。

阶段可以标记开始、完成或重新打开。已有内容的模块即使被停用也会保留数据；删除项目时先进入回收站，永久删除前应确认备份。

### 3.5使用AI时的正确顺序

1. 先在项目资料中明确主要参考、Brief、真实体验和不可编造的事实。
2. 发起任务前检查本次实际引用的资料。
3. 单AI适合连续讨论；双AI适合独立出稿后对比。
4. 候选只会创建新版本，不会静默覆盖当前内容。
5. 确认定稿后，再进入封面、标题和发布流程。

### 3.6安排工作

- 首页可查看今日待办、项目行动和周／月排期。
- `排期`页统一展示月、周、日和列表视图。
- 待办可以设置日期、时段、分类、项目、预计时长和完成方式。
- 常用项目或项目阶段可固定到侧栏，减少重复查找。

### 3.7管理收入

- `商单收入`记录平台订单、最终金额、返点、制作成本、投流成本、发票和回款状态。
- `其他收入`记录咨询、课程、授权、平台激励等非商单收入。
- 智能导入支持表格、文本、截图和PDF，但必须先生成可编辑预览，逐条确认后才写入。
- App不会登录网银、微信或支付宝，也不会自动修改收入记录。

### 3.8发布与分发

- 先在项目文案中设置定稿，再准备发布信息。
- 发布包会汇总标题、简介、封面、字幕、文件引用和检查清单。
- B站Computer Use目前是低频试验，只辅助上传和填写，最终发布必须由用户亲自确认。
- 批量分发只提供参考时间码和主题，不自动剪辑视频。

## 4.Android快速记录

### 4.1连接Mac

1. Mac和Android连接同一可信Wi-Fi。
2. Mac打开`设置→数据与设备→Android快速记录`并开启接收。
3. Android选择自动发现的Mac。
4. 两端出现相同6位数字时，在Mac上确认信任。
5. 首次信任后会自动同步；换Wi-Fi通常不需要重新配对。

### 4.2手机端能做什么

- 记录文字、录音、照片、图片、视频、PDF、Word和通用文件。
- 接收其他App通过系统分享发送的单项或多项内容。
- 使用快捷设置磁贴和桌面小组件快速开始记录。
- 在离线状态下继续保存；恢复连接后续传。

手机端不负责AI归类、OCR、转写和文案生成，这些工作统一交给Mac完成。设备密钥保存在Android安全存储中，传输内容使用加密协议。

## 5.数据、备份和隐私

- 工作区数据库、导入附件、AI配置、NAS配置和设备信任都位于各自电脑的App用户目录，不在源码仓库内。
- 启动时会自动创建备份，也可以在设置中手动备份和选择恢复点。
- 恢复备份前App会先保护当前数据，再重启完成恢复。
- NAS只接收用户明确选择的归档和备份内容；真实路径不回显到Renderer。
- 不要把用户数据库、备份目录、账单原件、发布账号信息、API key、Android签名文件或真实APK提交到Git。

## 6.从源码运行Mac端

### 6.1环境

- Apple Silicon Mac
- Node.js 24.x
- npm

### 6.2启动开发版

```bash
cd app
npm ci
CREATOR_OS_USER_DATA="$PWD/.local-data" npm run dev
```

### 6.3常用检查

```bash
cd app
npm run typecheck
npm run lint
npm test
npm run build
```

### 6.4生成安装包

先按[安装说明第4节](docs/安装与功能说明.md#4-构建测试和安装)准备自己的Whisper及Android可选资源，或调整自己的extraResources；这些本机资源不随源码分享。历史截图基线未上传，旧基线比较脚本需要自己重新建立基线。


```bash
cd app
npm run package:dmg
```

`package:dmg`在`app/dist/`生成DMG。当前工程没有面向公开分发的签名和公证配置，因此发给非开发者前，建议补齐Apple Developer签名、公证和自动更新发布流程。

项目维护者在本机安装验证时使用：

```bash
cd app
npm run package:mac
npm run package:smoke
```

`package:mac`会替换`/Applications/LY Creator OS.app`，朋友在自己的电脑上不要随意执行这个命令，以免覆盖已有安装版。

### 6.5本地字幕转写运行时

字幕转写需要Python 3.12、`faster-whisper`和本机`small`模型缓存：

```bash
cd app
PYTHON_BIN=/你的/Python3.12路径 ./scripts/setup-whisper-runtime.sh
```

生成的`.runtime/`体积较大并且不会进入Git。没有准备运行时前，可以开发和使用其他功能，但不能完成打包后的本地Whisper转写验证。

## 7.从源码运行Android端

需要Flutter、Android SDK、JDK和Android 12及以上设备或模拟器。

```bash
cd mobile
flutter pub get
dart analyze lib test
flutter test
```

第一次构建自己的release APK前，必须创建自己的本机签名：

```bash
cd mobile
./scripts/create-private-signing.sh
flutter build apk --release
```

签名文件保存在`mobile/android/.private-signing/`并被Git忽略。每个人都应保管自己的签名，不能共用仓库作者的签名；以后覆盖安装同一App时必须使用同一把签名。

## 8.常见问题

### 新安装为什么没有演示项目？

这是分享版的预期行为。新用户从空白工作区开始，避免看到作者的设备、客户、账单或项目案例。自动化测试需要演示数据时会在测试环境中单独启用。

### AI按钮不可用怎么办？

先到`设置→AI与发布`检查CLI登录状态，或添加API并验证连接。仅添加配置不会自动发起请求。

### Android找不到Mac怎么办？

确认两台设备在同一可信局域网，Mac已开启接收，防火墙没有阻断本App，并等待Bonjour广播完成。不要在公共Wi-Fi上配对。

### NAS显示未验证怎么办？

选择的目录虽然已经挂载，但真实设备上的大文件、断线和重试语义仍需单独验证。完成前不要把它当作唯一备份。

### 我只想把源码发给朋友，应该怎么做？

按照[《源码分享与隐私检查》](./源码分享与隐私检查.md)生成不带旧Git历史的源码快照，再上传到新的GitHub私有仓库。
