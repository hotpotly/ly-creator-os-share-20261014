# 安装与功能说明

本分享包含Mac工作台、Android源码、测试与构建脚本，不包含作者的数据库、商单、价格、脚本文案、账号密钥、签名和本机安装包。操作最详细的部分在[待办完整操作手册](待办完整操作手册.md)。

## 1 从哪里开始

1. 接受仓库拥有者发来的GitHub邀请，并登录受邀账号。
2. 克隆私有仓库，或通过`Code→Download ZIP`下载。
3. 准备Apple Silicon Mac和Node.js 24.x；在`app`目录执行`npm ci`。
4. 执行`npm run dev`打开开发版。开发版也会写本地数据，建议用独立工作区。

```bash
cd app
npm ci
CREATOR_OS_USER_DATA="$PWD/.local-data" npm run dev
```

`.local-data`已被Git忽略。不要把此目录、数据库或备份加入提交。新工作区为空白；不需要作者的账号和原始数据即可建立项目、待办和本地资料。

## 2 首次配置

在设置中逐项检查：外观主题、工作区和侧栏、待办分类、天气、默认平台、数据备份。需要AI时再配置自己的CLI登录或API；需要手机同步时再启用自己的设备配对；不使用的外部服务可以不配置。

本地保存不等于任何操作都不联网。AI请求、天气、联网资料、平台工具和设备同步有各自网络行为，发送文件前确认内容适合交给目标服务。

## 3 功能地图

| 模块 | 怎么用 | 关键边界 |
|---|---|---|
| 首页 | 查看待办、项目行动、排期、成长与投入，调整分栏 | 待办、预计与实际投入不是同一种数据 |
| 待办 | 三窗口同步、一小步、额外、批量创建、日期范围、进度、项目阶段、复制到今天、实际投入 | 看[完整手册](待办完整操作手册.md)，原日期任务不自动滚动 |
| 快速记录 | 顶栏入口或Command＋Shift＋Space，输入内容并附媒体 | 默认进入灵感，不自动变成待办 |
| 灵感库 | 处理收件箱、筛选、查重、归类、关联项目 | 原始内容保留；AI动作由用户发起 |
| 选题 | 填方向、角度、优先级、阶段、日期和下一步 | 确认制作后再建立项目 |
| 内容项目 | 新建项目并选模板，依次使用概览、资料、大纲、文案、制作、后期、发布 | 模块停用不等于删除既有内容 |
| 资料 | 导入文件／文件夹／网页／图片／PDF／笔记，标注主要参考 | 本机路径与附件不是源码；AI引用前核对 |
| 大纲与文案 | 手写或调用自己的AI；比较候选、修订、设定稿 | AI不能替你确认事实，候选不应静默覆盖定稿 |
| 制作和后期 | 拍摄／剪辑清单、阶段时间、字幕、本地转写、封面候选 | 标为规划的入口不当作已交付能力 |
| 发布 | 核对平台标题、简介、封面、字幕和发布交接 | 自动辅助不等于授权最终发布 |
| 排期 | 日／周／月／列表视图安排项目与行程 | 预计安排和实际开始完成时间分开 |
| 计划与复盘 | 周期目标、自由复盘、生活记录、经验记录 | 富文本样式默认收起；经验未自动合并进自由复盘 |
| 商务及收入 | 商单生命周期、返点、成本、发票、回款，其他收入及导入预览 | 首次没有作者数据；导入先核对再保存；隐私锁不是数据加密保险箱 |
| 数据与备份 | 手动备份、恢复、本机附件、可选NAS | 恢复影响整个工作区，NAS需自己验证 |
| Android | 离线采集、系统分享、媒体和局域网加密同步；源码含后续工作台范围 | 开发源码进度不等同已发布APK；授权范围外功能不要强开 |

### 推荐练习路线

先建一个非商单练习项目，导入一份不敏感资料，写一个大纲，建立三条待办。把一条关联到阶段，练习完成和恢复；另建昨天的任务，练习“复制到今天”，确认昨天原件还在。最后填写今天投入，做一次备份。熟悉后再导入自己的正式工作资料。

## 4 构建、测试和安装

```bash
cd app
npm run typecheck
npm test
npm run build
```

如果本机安装了Flutter，全量Mac测试还会执行跨端fixture；先进入`mobile`运行`flutter pub get`准备依赖，再回到`app`运行测试。

测试在隔离环境创建虚构数据。GUI回归使用`npm run test:e2e`，默认后台执行。历史截图基线没有放入分享包，因此`visual:verify-v8`、旧基线比较和整套依赖基线的阶段命令不能直接照搬；需要自己生成并审查新的基线。

### 历史端到端脚本的限制

旧的`r21h-work-log`、`r21r-todo-flow`脚本仍有旧选择器／旧阶段fixture不兼容（例如从旧“全部”按钮寻找已迁入视图菜单的入口）。本次检查记录了这些失败，没有修改产品功能或跳过断言来掩盖它们。不要把全部历史E2E视为已全绿；当前待办回归优先使用`r21ae-todo-date-range`、`r21af-todo-focus`、`r21t-todo-batch-link`、`r26f-todo-carryover`。

### Mac打包前的可选资源

打包配置会引用本地Whisper运行时／模型和私有Android分发资源目录，它们未上传。仅运行开发版或`npm run build`不需要作者的这些资源。

- 本地字幕转写：自行准备Python 3.12，再运行`PYTHON_BIN=/你自己的/python3.12路径 ./scripts/setup-whisper-runtime.sh`下载依赖和模型。注意下载体积与第三方许可。
- 不打包转写／Android安装包：在自己的分支里删除`package.json`中对应`build.extraResources`项；这会减少相应分发能力，不是缺少作者数据。
- Android安装包由自己构建，不能使用作者签名。

完成资源配置后用`npm run package:dmg`生成DMG。当前没有可供分享的Apple Developer签名与公证身份，需要自己配置；本分享不教绕过系统安全校验。

`npm run package:mac`会替换本机`/Applications/LY Creator OS.app`并打开，**不是无副作用的编译命令**。已有正式数据时，先备份并确认是否需要覆盖。安装后可执行`npm run package:smoke`；完整Smoke还要求本地转写等依赖齐备。

## 5 Android自行构建

准备Flutter、Android SDK、JDK及Android 12以上设备。进入`mobile`：

```bash
flutter pub get
dart analyze lib test
flutter test
./scripts/create-private-signing.sh
flutter build apk --release
```

签名文件不得上传。覆盖安装必须使用自己原来的同一签名，不要每次重新生成。真实设备的锁屏录音、后台保活、大文件、断网续传和系统分享需自己验证，不能只看模拟器通过。

局域网配对时，两端进入同一可信Wi-Fi，Mac启用接收，Android发现设备，对照两端验证码，再由Mac确认信任。外网服务、云费用和新的双向数据范围不因拿到源码而自动开启。

## 6 备份与安全

- 第一次正式使用前做一次备份；重要升级、导入和恢复前再备份。
- 不要复制作者的用户目录来“补配置”。每个人建立自己的数据库、API设置、设备信任和发布账号。
- App隐私锁用于限制界面访问，不替代系统磁盘加密、设备账号和安全备份。
- 手机、NAS、AI、发布平台等设置都使用自己的账号与设备。
- 发生误提交密钥时先撤销／轮换密钥；只删除最新文件不能抹掉Git历史。

## 7 私有分享的访问规则

只有仓库拥有者和获授权协作者可以查看私有仓库。仅转发URL并不能访问。收到404时先检查是否登录正确账号、是否接受邀请，不要把仓库改成公开来解决。

拿到访问权的人仍能下载和保留源码，因此只邀请信任的人。本仓库没有开放再分发许可证；再次公开或转交前联系作者确认。
